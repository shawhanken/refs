## 🔧 修复的测试

### Mempool 测试修复

**文件**: `chain/src/mempool.rs`  
**测试**: `test_add_transaction_with_same_nonce_dropped`

**问题**:
```rust
// 原始代码：两个交易完全相同，导致digest相同
let tx1 = Transaction::sign_multi(..., 50_000, 50_000, ...);
let tx2 = Transaction::sign_multi(..., 50_000, 50_000, ...);
// tx1和tx2的digest相同，无法测试"相同nonce不同交易"的场景
```

**修复**:
```rust
// 修复后：tx2使用不同的gas limit
let tx1 = Transaction::sign_multi(..., 50_000, 50_000, ...);
let tx2 = Transaction::sign_multi(..., 60_000, 50_000, ...); // 不同cycles_limit
// 现在tx1和tx2有相同nonce但不同digest
```

## 📋 Checkpoint 模式演示

### Deferred Transaction 演示方案

**场景**: 长时间运行的任务（例如：批量处理数据）

**流程**:
```
Block N:
  1. 用户发送交易 → Actor 开始处理
  2. Actor 执行到某个检查点
  3. 保存 Checkpoint 状态到 storage
  4. 创建 Deferred Transaction
  5. 返回（当前块完成）

Block N+1:
  6. Deferred Transaction 被包含
  7. Actor 从 Checkpoint 恢复
  8. 继续处理剩余任务
  9. 完成或创建下一个 Checkpoint
```

**技术要点**:
- **Checkpoint 模式**: 状态存储在 `__continuation:{message_id}`
- **Deferred Transaction**: 使用 origin_tx_hash 关联原始交易
- **协作**: Checkpoint 保存执行状态，Deferred Transaction 触发恢复
