# Devnet 版链上 Basefee 经济设计：演进说明与对比摘要

**文档日期：** 2026-04-12  
**适用范围：** Cowboy 节点 **`devnet` 版**（开发网 / 测试网形态）的共识参数与实现（非主网承诺）。  

---

## 1. 执行摘要

Cowboy **devnet 版**采用 **CIP-3 风格的双资源计量（Cycles / Cells）** 与 **双轨 EIP-1559 式 basefee**：计算与数据分开定价，并各自根据块内用量相对目标值进行算法调节。  

在 **devnet 版** 演进过程中，**定价公式骨架保持稳定**；变化主要集中在：**块内 cycle 预算与车道分配**、**EIP-1559 目标值**（\(T_c\)：每块 **计算** 目标用量，Cycles；\(T_b\)：每块 **数据** 目标用量，Cells，1 Cell = 1 byte）、**创世初始 basefee**、**失败交易是否付费**、**小费归属**、以及 **gas 从哪个账户扣除（发送者 vs Actor/所有者）**。  

**当前 devnet 版**与 CIP-3 正文中的部分数值（如车道比例、\(T_c=10\text{M}\)（计算目标）等）**存在有意或无意的偏差**，以 **吞吐压测与运行稳定性** 为优先；正式对外规范需单独做一次 **链上常数 vs 文档** 对齐。  

---

## 2. 演进时间线（devnet 版）

下列阶段依据 **devnet 版** 的迭代与实现演进归纳；阶段边界为逻辑划分，非严格发布版本。

| 阶段 | 主题 | 要点 |
|------|------|------|
| **A** | 双计量 + 双 basefee 落地 | 引入 `cycle_basefee` / `cell_basefee`，独立 EIP-1559 更新；早期 `BLOCK_CYCLES_TARGET = 5M`，`BLOCK_CELLS_TARGET = 500k`；初始 cycle/cell basefee 曾不对称（如 cycle 1e9、cell 1e8）；`ALPHA = 8`（单块最大约 ±12.5%）。 |
| **B** | 白皮书叙述对齐 + 块级生命周期 | 目标调至 **10M cycles / 500k cells**；**0x06** 固定为 DualBasefee 系统 Actor；`process_block` 与 `ExecutionEngine` 负责加载、执行中累计、按父块用量更新并写回；投机执行（speculative）批量模型成型。 |
| **C** | 安全审计：激励与抗滥用 | **失败交易仍扣费并推进 nonce**，避免“失败零成本”垃圾流量；**basefee 对应部分销毁至零地址**；**小费支付给当前块提议者**（由 leader 公钥派生地址），修复“小费误烧、损害出块激励”类问题；部分结算逻辑收拢至 speculative 层。 |
| **D** | 支付主体：Actor 付费 | **优先从 Actor 余额扣 gas**；可通过 **`UseOwnerBalance` 授权**回退到所有者余额，再回退到交易发送者；支持 **`FundActor`** 等为链上账户注资。不改变 basefee/tip 公式，改变的是 **谁买单**。 |
| **E** | 吞吐：车道扩容与目标再标定 | System 车道由约 **5M 提升至 25M** 等；**`BLOCK_CYCLES_TARGET` 与四车道总和**按“最大单车道饱和即可顶满单块涨幅上限”的思路重标定；**当前 devnet 版**约为 **\(T_c \approx 12.5\text{M}\)**（每块计算目标）、**\(T_b \approx 2.5\text{M}\)**（每块数据目标）、四车道合计 **50M**。 |
| **F** | 可观测性 | Benchmark 与指标侧强化 basefee 跟踪与报告，便于压测与调参。 |

## 3. 各阶段能力变化（优势与代价）

| 变迁 | 带来的能力 | 代价、风险或与文档的张力 |
|------|------------|---------------------------|
| 双轨 basefee | 计算与数据 **分开竞价**，长期更易分别出清两类资源 | 用户/钱包需处理 **两维 max_fee 与两维 tip**，复杂度更高 |
| 目标与车道调整 | basefee 对 **真实块内瓶颈** 的反应与产品吞吐目标更一致 | 与 CIP-3 中固定表格数值 **易不一致**，需文档或常数二选一跟进 |
| 初始价由不对称到对称、整体降低 | 测试网 **更便宜、更对称**；利于生态试错 | 若迁移主网需 **重新评估创世经济** |
| 失败也扣费 + tip 给提议者 | **抗垃圾**、**出块激励正确** | 用户 **失败也损失手续费**，需产品提示 |
| 费用在 speculative 层聚合 | 块级 burn/tip/basefee 与 **批量执行/验证** 一致性好 | 实现跨 `execution` 与 `storage`，排障成本高 |
| Actor 付费 + 所有者回退 | DApp 可 **自付 gas**，降低终端用户持币门槛 | 授权与余额模型 **审计面更大** |
| `ALPHA = 8` 且块时间约 1s | 与文档常见写法一致，实现简单 | 相对以太坊 12s 块，**同等 α 下每秒调节更猛**，短期费率波动可能更大 |
| Basefee **下调下限**（`MIN_BASEFEE`） | 为 EIP-1559 式更新提供**协议地板**，与 **创世/默认起步价**（`INITIAL_*_BASEFEE`）是不同概念 | 具体数值**随版本与部署变化**；对外沟通宜以**当次链上读数或发布说明**为准，避免与某一历史测试常数绑定 |

## 4. 过去 / 现在 / 目标方向 对比表

**“过去”** 合并 **devnet 版** 早期（首版双 basefee 至白皮书对齐前后）的典型状态；**“现在”** 以 **当前 devnet 版** 实现（如 `types/src/constants.rs` 等）为准；**“目标方向”** 归纳经济设计与协议演进上的 **意向重点**，便于与客户对齐预期——**不构成**固定排期或交付承诺。

| 维度 | 过去（早期 devnet 版） | 现在（当前 devnet 版） | 目标方向 |
|------|---------------------|---------------------|--------------|
| 双轨 basefee | 已存在 | 同左 | **维持**；与规范对齐或修订文档 |
| EIP-1559 灵敏度 | `ALPHA = 8`（约 ±12.5%/块） | 仍为 8 | **可能**试验更大 α 以匹配 1s 块；**devnet 版** 上 **尚未**改 |
| \(T_c\)（每块计算目标，Cycles） | 5M → 曾 10M | **12.5M** | **继续随吞吐调** \(T_c\) |
| \(T_b\)（每块数据目标，Cells） | 500k | **2.5M** | 与 \(T_c\) **联动** |
| 车道总预算 | 较小 System 车道 → 后扩容 | 合计 **50M**，System **25M** | **偏性能**；规范表格易过时 |
| 初始 basefee | cycle 1e9、cell 1e8（曾不对称） | cycle/cell 均为 **1e8** | 测试网友好；主网需 **重评** |
| basefee 销毁 | 设计为销毁 | **→ `Address::ZERO`** | **维持** |
| Tip 归属 | 实现曾存在风险 | **→ 当前块提议者** | **巩固**激励 |
| 失败交易费用 | 存在免费窗口 | **失败也付费** | **继续**收紧免费路径 |
| 扣款账户 | 主要为发送者 | **Actor → 授权所有者 → 发送者** | **应用自付** 更常见 |
| 结算位置 | 偏单笔路径 | **speculative 块级聚合** | **维持**块级模型 |
| 与 CIP-3 一致性 | 已偏离早期数值 | **仍部分偏离** | **链上常数或 CIP 必择一更新** |
