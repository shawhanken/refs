01系统构成

Homestead 是 macOS 原生 Markdown 协作工作区:免费本地模式不需账号,付费云端模式把协作、存储、计费跑在 Cowboy 自己的链上基础设施上。它同时是用真实产品压测整条 Cowboy 技术栈的载体 —— 这意味着它的交付路径穿过 node、gateway、cbqs、cbfs、cowboy-protocol 五个仓。

apps/Homestead/ SwiftUI 外壳 · 135 文件 / 48.5k 行
webeditor/ CodeMirror 6 + Yjs,单文件内联进 WKWebView · 20.7k 行 TS
crates/homestead-{core,ffi}/ SQLite 缓存 + UniFFI 桥(29 方法) · 12.3k 行 Rust
actor/homestead.py 链上 actor:成员、页树、ACL、计费授权 · 14.7k 行
services/collab-relay/ 独立部署的 Yjs 中继 + 嵌入式 CBFS · 37.1k 行 Rust
services/{billing,storage-provisioner,dev-readiness}/ · store/ 计费、存储供应、dev 就绪签名、CIP-33 上架包
仓内有两条并行的产品线

main 是云端/基础设施线(actor、中继、CBQS、计费、证明闸);origin/devnet 是产品/编辑器线(Notion 本地化导入、只读 HTML 查看器、侧边栏键盘导航、Gallop 设计 token),领先 5 个 commit,定期把 main 同步进来。两条线目前对 v1 形态的假设并不一致,详见 §10 漂移第 4 条。

02端与协议

下图是一次云端页面打开实际经过的端与协议。值得注意的是中间那条绿线:编辑器并不是把所有流量都交给 relay —— 它先向 relay 领取凭证,然后直连 CBQS broker。

图上三处值得单独记住

1 · 编辑器与 broker 是直连的。 relay 只负责铸出 lane 限定的 StreamGrant,之后的 CRDT 记录走客户端到 broker 的 wss。这意味着 broker 端点必须对客户端可达 —— 原生客户端与浏览器都拒绝非 loopback 的 ws://。

2 · 公开分享页不是 web 客户端。 GET /s/:guid 是服务端渲染的只读 HTML,CSP 为 default-src 'none'、no-store。因此权限格里的 comment 级公开链接,目前没有对应的浏览器交互面。

3 · 虚线的两个箱子决定其余部分能否启用。 billing 与 provisioner 未部署、role-driver 未合入主线,workspace 因此停在 pending / created,写入返回 409。

目前唯一的可写路径是 dev-only 构建

CloudTrustBuild.swift 在编译期只产出一个信任 profile:production-chain-storage-v1(要求 provisioning_state=active),或 proof-bound-development-embedded-v1(接受 dev_ready)。后者仍要求真实的链上 hire 与真实的 CBQS finalized stream proof,只是把信任根换成一个 dev-only 密钥 —— 生产构建会把它编译掉并拒绝。演示与生产之间因此存在一条明确的分界线。

06这个栈的失败形态:静默成功

已经遇到的缺陷有一个共同形状:命令返回 0、CLI 打印 tx hash、测试全绿、日志无报错 —— 而实际什么都没有发生。这类问题不会被静态检查或单元测试发现,只在实际运行中暴露。

事件表面现象实际原因
0828 演示中断 交易提交没有反应 gateway 钱包低于每笔交易声明的 4,250 CBY 最坏成本,节点拒绝入池 —— 在 node#1461 之前是静默拒绝
所有页面打不开 会话握手全部正常,随后无内容 部署的 cbqsd 与浏览器 wasm 对「无记录 fast lane」的 origin trailer 判读不同,客户端 fail-closed。两边各自都自洽
快照器不工作 订阅成功、无任何错误、零投递 订阅以零信用额度打开,broker 不投递本身就是协议正常行为,因此没有错误可报
CBQS 建流被拒 CLI 打印 tx hash,看起来成功 三种原因同一形态:retention 默认 7d 超过 fast 24h 上限、provider base-rate 预留在第十条流后耗尽、未导出 COWBOY_PRIVATE_KEY。只有 stream-close 会返回上限
磁盘写满 extern location for X does not exist、后台命令空输出 磁盘 100%,从不报告为磁盘错误。约 1 TB 是 35 个 worktree 的 target/
团队自己总结的两条(直接来自交接文档)

「绿或红都不是证明。」 一次全套 209/0 通过,几分钟后同一套件命中 15% 概率的竞态;该修复的验收标准定为 6-in-40 → 0-in-60,而不是「下一次跑绿」。反向也成立:一次重跑通过不是 flake 的证据 —— 那个判断做早了,结果把 devnet 弄红。

「规格里记下的决定,在到达实现之前不算决定。」 CIP-39 的 v2 回退在规格里躺了十二小时,codec 与 broker 同期发布的是相反的东西;PR 审得很干净,因为 diff 自洽,只有 CIP 不同意。结果是一整层多余的 V2 协议被 19 个文件消费,事后删除 −684 / −386 行。

07依赖链

部署链 —— 每一步消费上一步的产物

node/homestead→ gateway/homestead→ collab relay→ actor set_routes→ 钱包注资

顺序不可颠倒:gateway 消费 node 的新 wire surface(/proof/account 排除证明、submit_wait 类型化错误),对着旧 node 会永久报 readiness-unknown —— 这是 fail-closed 的设计行为,不是故障。

激活链 —— 每一环都需要上一环的真实凭证

role-driver 合入主线→ KMS 托管密钥→ 两个私有 CBFS 卷→ manifest v2 + 重启包装→ 中继 ready receipt→ actor 转 active→ Stripe 生产账号→ 可写 workspace

红 = 代码尚未合入主线,黄 = 依赖外部方。

整个栈是 fail-closed 的

陈旧收据、绑定失败、监督器 panic、摘要不符、token 剩余时间不足、子进程效果不确定、超时 —— 全部判为 reconcile 而非 ready。协调器拒绝在缺少真实凭证时放行。这是它值得信任的原因,也意味着链条上的每一环都必须按顺序真实完成。

09尚无证据的部分

以下每一项目前的证据量都是零 —— 不是「做过但有问题」,而是尚未执行过。

备份还原 —— 协调器有 14 个密封测试,真实的 private-CBFS 快照、上传与还原一次都没有做过。
Smoke Phase B / C —— Phase A 曾被 origin 缺陷阻断(已解决),B 与 C 从未运行。
多 workspace 爆炸半径与还原演练 —— 需要真实 KMS/CBFS 凭证,并证明日志、收据、计费状态中不泄密。
463 页 Notion 语料验收 —— 语料需人工提供;合成 archive 通过不等同于真实导出通过。
性能预算 —— 暖开 <300ms / 冷开 <1.5s,尚未对签名版本与真实语料测量过一次。
浏览器端真实快照 join —— 单元路径已覆盖,对着活的快照的真实 join 没有跑过。
CBQS wasm 字节等价闸 —— 浏览器验证器与原生验证器没有比对语料;目前是 verified-by-construction,不是 verified-by-gate。cbss-wasm 有此闸,CBQS 没有。
cbqs 的 Marshal 覆盖 —— 从未审过任何内容(0 条,对比 node 的 454);cowboy-protocol 的不变量闸返回空数组。
耐久性

0827 的记录中,被钉住的那个页面处于「按设计已死」状态:lane 在 1 小时保留期下被裁剪,而快照器在集群上已发布的 generation 数为零。也就是说,若快照发布没有真正持续运行,内容在保留期之后不可恢复。

该状态需要对当前集群复核。它指向的是一个结构性事实:目前还没有一份「数据在集群上确实持久」的证据。

10不可逆与单点环节

  • actor 部署后不可升级。 创世后部署的 actor 收不到 sys.upgrade。每次改动 = 部署新 actor + 一次性 owner 迁移 + 安装路由 + 重指客户端,旧 actor 需保留到新的验证完毕。这里出错的代价是迁移状态,不是回滚一个 commit。
  • genesis reset 是破坏性的。 链上状态不保留;之后需重注册 runner、重注资钱包,且 chain_instance_id 在 genesis 文件相同时会存活,必须使用新 nonce。
  • squash 合并后必须重新 pin。 已经踩过一次:被 pin 的分支 sha 从来不是一个已合入的修订。
  • 单验证者链。 当前 chain_id=1862 是单验证者,不具备生产的可用性形态。
  • tailscale authkey 的密钥版本已被销毁,重启的机器会掉出 tailnet(非致命,IAP ssh 仍可用),需要轮换。
  • dev-only 信任根与生产信任根是两个编译产物。 二者在外观上没有区别,但生产构建会拒绝前者。
