Appendix: 4 issues carrying an erratum we resolve ourselves

This section is a note only and is not counted in any figure on this page. All four are already included in Phase 1, 2 or 3 above (marked * in the weekly, blocked and November tables) and are not counted again here.Their descriptions diverge from the current CIP, but they need no input from the Cowboy team: the specification itself is clear and the issue text is simply wrong, so correcting it involves no choice between amending the CIP and amending the issue, which is why they are not in the Errata & Decision Sheet. Below is how we will handle each one.

IssueCIPIssue IDsHow we will handle it
COW-1111*CIP-23[Node/Runner] NVIDIA NCC GPU attestation (NRAS token + verification)The issue coins a type name `RunnerResult` that does not appear anywhere in CIP-23. Our own call: align to CIP-23's existing naming; no CIP change.
COW-1200*CIP-22[Examples] Reference auction example actor at examples/<NN>-cca/The issue cites “CIP-22 line 873: See examples/cca/”; that line is now the §Example: Token Launch snippet, with the reference implementation under §Reference Implementation. Our own call: update the citation; no CIP change.
COW-1910*CIP-28§4.4 Edge-case handling (frozen/expired after reserveThe issue text still assumes CIP-28 is spec-only, and lists 6 of the 8 §4.4 edge cases. Our own call: update the description to match devnet and add the two missing cases; no CIP change.
COW-2504*CIP-10CIP-10: TEE-signed BillingAttestation (CIP-23 CompositeAttestation)The issue says `0x11` calls `0x05::VerifyCae`, but the Container Registry is at `0x13` (`0x11` is the validator-set snapshot). Our own call: correct it to `0x13` per WP §9.1 and the code; no CIP change. Must be fixed before coding — implementing it as written would route verification to the wrong system actor.
