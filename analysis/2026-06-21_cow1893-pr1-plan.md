# COW-1893 PR1 — CIP-24 §5.3 error vocabulary (reserve all + wire release/receipt) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Reserve the full CIP-24 §5.3 canonical error vocabulary as E17xx codes (non-consensus) and wire the `handle_cbss_submit_release_receipt` failure sites to their named errors (consensus).

**Architecture:** Three additive layers move together per error — `ExecutionError` variant (`execution/src/error.rs`), code registry `ErrorSpec` (`storage/src/error_codes.rs`) + doc line (`docs/errors/README.md`), and variant→code map arm (`execution/src/structured_error_map.rs`). Task 1 reserves all 28 new errors at codes 1706–1733 (no handler returns them yet = non-consensus). Task 2 splits the combined `||` guards in the release-receipt handler and returns the specific named error per §5.3, one guard at a time with a test per code.

**Tech Stack:** Rust (cowboy-execution, cowboy-storage), the existing `StructuredError` / `error_codes` registry.

**Worktree:** `/home/ubuntu/.config/superpowers/worktrees/node/cow-1893-error-vocab`, branch `fix/cow-1893-cbss-error-vocab`, base `devnet`. Set `export CARGO_TARGET_DIR=$PWD/.cargo-target` before cargo. Do NOT `git push` or switch branches.

### Task 2: Wire `handle_cbss_submit_release_receipt` failure sites (CONSENSUS)

**Files:** `execution/src/cbss.rs` (`handle_cbss_submit_release_receipt`), tests in the same file's `mod tests`.

The handler currently collapses several distinct conditions into combined `||` guards that all return `ExecutionError::InvalidData`. Split each guard so every named §5.3 condition returns its specific error. Convert + test ONE guard at a time. Conditions with no §5.3 name (e.g. `request_block > block_height` future request, `set.threshold != release_key.threshold` config mismatch, missing version/proxy records) KEEP `InvalidData`.

- [ ] **Step 1: Test — freshness/ordering/epoch guard split**

Add to `mod tests` (model existing submit-receipt tests, e.g. `submit_release_receipt_serve_epoch_mismatch`, for fixture setup via `receipt_fixture`). Assert the *code* via `into_structured`:
```rust
#[tokio::test]
async fn submit_release_receipt_named_errors_freshness_ordering_epoch() {
    use crate::structured_error_map::IntoStructured;
    // stale request_block -> E1719 StaleRequestBlock
    let mut f = receipt_fixture(false, true).await;
    f.args.runner_request.body.request_block = 0;
    f.block_height = REQUEST_FRESHNESS_BLOCKS + 10;
    let e = HttpExecutorless::submit(&mut f).await.unwrap_err(); // see helper note below
    assert_eq!(e.into_structured().code, 1719);
    // served_at_block < request_block -> E1728 ReceiptOrderingInvalid
    let mut f = receipt_fixture(false, true).await;
    f.args.served_at_block = f.args.runner_request.body.request_block.saturating_sub(1);
    assert_eq!(submit_err(&mut f).await.into_structured().code, 1728);
    // committee_epoch_at_serve != serve_epoch -> E1730 MixedEpochReceipts
    let mut f = receipt_fixture(false, true).await;
    f.args.committee_epoch_at_serve = f.args.runner_request.body.serve_epoch + 1;
    assert_eq!(submit_err(&mut f).await.into_structured().code, 1730);
    // sigma_i all-zero -> E1726 InvalidPartialReencrypt
    let mut f = receipt_fixture(false, true).await;
    f.args.sigma_i = cbss::G1Bytes([0u8; 48]);
    assert_eq!(submit_err(&mut f).await.into_structured().code, 1726);
}
```

Use the exact signature from `submit_release_receipt_serve_epoch_mismatch`. (Adjust `G1Bytes([0u8;48])` to the real `sigma_i` type/len in `SubmitReleaseReceiptArgs` — confirm at implementation.)
